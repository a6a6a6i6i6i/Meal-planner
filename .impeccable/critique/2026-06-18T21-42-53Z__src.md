## Anti-Patterns Verdict

**LLM assessment**: Low-to-moderate slop. The design avoids the biggest tells — no generic hero gradients, no hollow identical card grids, no rainbow icon sets. The Fraunces + Inter pairing is a committed design decision, not a default. The warm cream surface hierarchy is specific (four levels: background → surface-soft → surface-card → surface-strong). The animation system is semantically intentional — each keyframe class has a distinct communicative role. Minor tells: the 10px uppercase tracking label appears in 6+ locations (slot labels, macro labels, day-name, week-number, "Total", ingredient subtext) becoming a stylistic tic rather than a deliberate system. Emoji in empty states (📋, 🥗) is a common AI shorthand for "delight" that feels incongruous with the otherwise typographic system. The idle shimmer conic gradient on "Add meal" reads as a generic rainbow-shimmer pattern widely seen in AI UIs.

**Deterministic scan**: 1 finding — `overused-font` warning for Inter in `src/index.css:80`. Inter is ubiquitous in AI-generated UIs. The Fraunces pairing elevates the design significantly, but Inter as the body/UI face remains a recognizable AI default. This is a legitimate signal — not a false positive — though the combination with Fraunces partially redeems it. No gradient-text, no side-stripe borders, no eyebrow-on-every-section, no hero-metric template detected.

## Overall Impression

A well-considered tool with a genuine design voice (that animation system is genuinely good, and the surface token hierarchy is intentional). The biggest opportunity is fixing the **no-undo delete** path — a single misclick on a trash icon can silently cascade across weeks of planning data, and that's a trust-breaker. Second biggest: the **goals labeling inconsistency** is likely causing silent incorrect tracking for a meaningful percentage of users who read "Weekly goals" and enter a weekly total. The visual and interaction polish is high; the information architecture has 3–4 specific gaps that undermine the core use case.

---

## What's Working

1. **Animation system is semantically rich**: `slot-fill-glow`, `today-col-pulse`, `macro-bar-expand`, `swap-col-flash` — each class communicates a distinct state. The `prefers-reduced-motion` block covers all 14 animation classes correctly. This is unusually disciplined.

2. **Surface token hierarchy**: four levels (background → surface-soft → surface-card → surface-strong) create genuine depth without shadow-proliferation or heavy borders. The warm cream palette is specific and holds in both light and dark modes.

3. **SwapSuggestion is genuinely smart**: proactively surfacing a macro-optimization recommendation rather than leaving analysis to the user is a meaningful UX differentiator. It makes the app feel like an active assistant.

## Priority Issues

### [P0] No undo on library delete — cascading silent breakage
**Why it matters**: Deleting a meal from the library instantly renders every slot that references it as a red "Meal removed from library" error state — across all stored weeks, with no warning and no recovery path. A single misclick destroys planning data irreversibly.
**Fix**: Add a confirmation AlertDialog before firing delete, showing how many planner slots reference the meal. Then add a sonner `toast.success` with an `action: { label: "Undo", onClick: () => restoreMeal() }` pattern, holding the deleted meal in a 5-second ref before committing to localStorage.
**Suggested command**: `/impeccable harden`

### [P1] "Weekly goals" vs "kcal/day" inconsistency — silent tracking errors
**Why it matters**: GoalsDialog title says "Weekly goals", fields say "kcal/day", header pills show bare numbers. A user reading "Weekly goals" and entering 14000 thinking it means 2000/day will see every day perpetually under-goal. This is a silent data corruption issue disguised as a labeling bug.
**Fix**: Pick one frame (per-day is the fitness standard). Rename dialog title to "Daily goals". Add "/day" suffix to pills. Add a one-line subtext under the dialog title: "Targets applied to each day of the week."
**Suggested command**: `/impeccable clarify`

### [P1] No macro breakdown per slot — fitness users can't diagnose over-budget days
**Why it matters**: Slots show only meal name + total kcal. To identify which meal is blowing a carb budget the user must compute day totals mentally across 3 slots. The primary user of a macro tracker needs per-meal macro visibility.
**Fix**: Under each assigned meal name in MealSlot, add a compact row: `P 42g · F 12g · C 68g` in the same 10px muted style already used for labels. This replaces the lonely standalone kcal line.
**Suggested command**: `/impeccable layout`

### [P2] No search/filter in Meal Library — degrades at 20+ meals
**Why it matters**: At scale the 4-column grid requires full visual scan to find a meal. MealPicker (used for slot assignment) has the same problem. The idle shimmer on "Add meal" actively encourages growth with no organizational affordance to match.
**Fix**: Add a search `<Input>` with Search icon prefix at the top of MealLibrary, filtering `meals` by name case-insensitively. Expose the same filter string to MealPicker.
**Suggested command**: `/impeccable craft search for meal library`

### [P2] MealForm ingredient macro entry has no guidance
**Why it matters**: The per-gram macro entry workflow is the most cognitively demanding part of the app and has zero inline help. Users may not realize entered macros auto-scale with gram changes, or that they're entering per-serving totals (not per-100g). A user who misreads the interface corrupts every week that uses that meal.
**Fix**: Upgrade "Per Xg" caption to "Macros for exactly Xg" with `font-medium`. Add a `?` tooltip explaining auto-scaling. Consider a toggle for per-100g entry for users copying from nutrition labels.
**Suggested command**: `/impeccable clarify`

## Persona Red Flags

**Fitness-focused daily user**
- Cannot see per-meal protein/fat/carbs — must mentally reconstruct from day totals to identify which slot blew their budget
- No keyboard shortcuts; no drag-and-drop between slots
- SwapSuggestion optimization criterion is opaque — cannot trust a recommendation they can't verify
- No weekly aggregate view (7-day totals) for retrospective validation
- No per-day goal variation (training vs. rest days)

**Casual occasional user**
- MealForm ingredient entry (4-column number grid per ingredient) is the first major interaction after library empty state — immediate drop-off risk
- "Weekly goals" label likely causes them to enter weekly totals, silently breaking all macro tracking
- No template or starter meals — the empty library requires prior knowledge of their own macros before the app delivers any value
- "Week 32" ISO label meaningless outside of Europe/ISO regions
- 10-second idle shimmer on "Add meal" reads as a loading/error state to a non-power user

**Mobile user**
- No scroll position indicator — no dots, no pagination, no partial-peek of the adjacent day column to signal horizontal scrollability
- Explicit `[scrollbar-width:none]` removes the only visual affordance that scrolling is possible
- `ChevronDown` in the nudge banner says "look below" but on mobile the action is horizontal scroll — wrong direction
- MealForm on mobile is a 4-column number grid inside a `max-h-[90vh]` dialog — very hard to interact with on 375px viewport
- WeekHeader with `min-w-[240px]` date block + nav arrows + goals pills + edit button at narrow widths — potential overflow risk

## Minor Observations

- `GoalPill` uses `key={pill.label}` where label includes the dynamic value ("2000 kcal") — key changes on every goal edit, causing unmount/remount instead of update, defeating the `goal-pill-pop` animation
- `findBestSwap` runs on every render of every DayColumn — if computationally heavy (7 columns × all meals × all slots), should be `useMemo`-wrapped
- Dark mode surface palette is heavily teal-dominant (180°) vs. the warm cream light mode (40–46°) — switching modes changes the emotional register significantly; may be intentional but creates a split-personality design
- `MealCard.handleDelete` uses `setTimeout(onDelete, 160)` — should use `onAnimationEnd` to avoid timing drift in concurrent React 18
- Week number label ("Week 32") is meaningless to users in non-ISO regions; relative label ("This week" / "Jun 9–15") would serve more users
- MealForm auto-scales macros silently when grams change — no visual indication the numbers updated, which can startle mid-entry users

## Questions to Consider

- GoalPill renders with `key={pill.label}` — is the goal-pill-pop animation intentionally designed to play on every goal-value change, or should it play only on the first render? The key bug means it currently plays on every change.
- SwapSuggestion (`findBestSwap`) — what is the objective function? If it optimizes calories only, it may recommend cheesecake to hit a protein goal. Has the algorithm been validated against realistic meal libraries?
- Why is the dark mode surface palette teal-dominant (hue 180°) while the light mode is warm-cream (hue 40–46°)? This feels like two different apps — was this an intentional brand decision?
- The idle shimmer triggers after 10 seconds of inactivity — but a user pausing to think about what meal to add is cognitively busy, not idle. Has this been validated against the actual reasons users pause on the library page?
- Could a "Copy this week" feature eliminate the single biggest efficiency gap (re-planning identical weeks) without requiring drag-and-drop or keyboard shortcuts?
